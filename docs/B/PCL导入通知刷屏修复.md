# PCL 导入通知刷屏修复

## 问题

Issue #10 中的“操”并非程序输出脏话，而是通知中的“操作”被窄宽度拆成两行。原进度回调为每个文件创建持续五秒的独立通知，数千个文件的通知堆叠后遮挡实例选择和启动按钮；长资源哈希进一步导致换行。

## 修改

PCL 和 `.mrpack` 导入均不再发送开始、阶段、文件、完成或失败弹出通知。选择来源后创建一个任务并打开已有任务中心；阶段说明、文件计数和阶段内百分比更新到这一个任务卡片。错误详情留在任务中心，取消按钮传递同一个 CancellationToken。

`ImportTaskRunner` 在后台执行导入，串行合并并限频高频进度回调。只有导入方法正常返回才设置 100% 和已完成；失败保留 Exception，取消不转为成功，结束后忽略迟到的进度。移除以 `PCL/Setup.ini` 为唯一资格判断的通知分支，由导入器解析实际版本文件。

本 PR 不修改加载器选择、依赖迁移或 Forge 安装逻辑；精确实例导入及内容迁移计数由 #13 修复，组合构建同时包含两项修复。此前仅过滤文件通知的方案已被这次“零导入通知 + 单个任务”替代。

## 验证

在 Windows x64、.NET SDK 10.0.302 上独立构建桌面项目成功，0 错误；已有项目警告仍存在。新增 6 项回归覆盖 10000 次文件回调限频、单个任务、零通知、成功／失败／预先取消、真实任务中心取消命令、提前 Done 后失败、迟到回调和真实 XAML 绑定。上游原 34 项 UI/JSON 断言仍通过。

静态检查两个首页导入入口均无 `MainWindowShowFlyoutMessage` 和 `OlanExceptionWorker` 调用。headless 渲染已检查真实任务中心的运行中、已取消及失败卡片；这是隔离测试数据，不是真实整合包导入录屏。

本次 PR 拆分没有再执行桌面导入录屏；不把构建成功当作完整 UI 验收。
