# OneLauncher 前端设计规范
- 该文档给Agent用户撰写项目前端部分进行设计规范（人类也可以参考），该设计规范必须严格执行
- 请参考UI_FI.md进行前端View（.axaml）部分的设计，本次文档着重介绍ViewModel，优先级高于UI_FI.md。如果参与View部分设计，UI_FI.md和UI_FI_Style.md为必读文档

## 前端定义
OneLauncher.Desktop为项目的前端启动项目，不允许更改。OneLauncher项目才是项目中真正的前端部分。

## 针对UI设计中存在列表项的情况
本项目中的前端设计出现列表项的情况很常见，具体体现为ListBox控件，内部有多个ListBoxItem
一般而言View层设计如下（引用gamedata.axaml）
```
<ListBox Classes="card-list" ItemsSource="{Binding GameDataList}" SelectionMode="Multiple">
	<ListBox.ItemTemplate>
		<DataTemplate x:DataType="vm:GameDataItem">
            <Border Classes="data-card" Padding="10">
            	<Grid>
                </Grid>
            </Border>
		</DataTemplate>
	</ListBox.ItemTemplate>
</ListBox>
```
在这个例子中，ViewModel层的设计包含以下特征：
- 对于ListBoxItem较为复杂的情况，会存在一个继承于BaseViewModel的XXXItem类来描述ListBoxItem的行为
- ViewModel实现 IListTemplate 接口

## 通用情况
- 使用CommunityToolkit.Mvvm进行代码现代化，比如[ObservableProperty]和[RelayCommand]生成属性和事件
- 操作的开始和结束使用以下代码来通知用户
```
WeakReferenceMessenger.Default.Send(
    new MainWindowShowFlyoutMessage(String.New()));
```
- 使用OlanExceptionWorker处理后端的错误
- ViewModel，Page实现 IPageHost接口，Pane实现 IPaneHost接口

## 依赖注入
- 项目使用Microsoft.Extensions.DependencyInjection作为依赖注入框架，在后端在Init.cs中初始化和UnitedCore，后端声明需要添加到依赖注入的管理器；前端在MainWindow.cs，前端声明需要使用管理器的ViewModel组件
- ViewModel构建函数直接声明需要的管理器，然后添加一个private readonly字段来保存该单例
- 添加的子Pane需要使用时通过此传入
