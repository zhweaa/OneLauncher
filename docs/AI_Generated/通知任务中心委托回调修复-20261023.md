# 通知任务中心委托回调修复

## 问题与证据

用户报告点击通知时在 ShowFlyout 第 192 行创建关闭回调处抛出 `ArgumentException: Delegate to an instance method cannot have null 'this'`。

当前源代码这一行包含嵌套 lambda 的委托创建。检查当前编译产物的 IL，发现关闭 lambda 的捕获对象由 newobj 创建，源代码中也没有直接将 null 实例的方法转为委托。因此现有证据不能确定该异常的具体根因，也不能直接归因于工厂、Page ViewModel 或某个编译模式。本次将回调改为显式实例方法，并加入运行路径回归验证；未复现用户此前进程中的原异常。

## 实现与文件

- `OneLauncher/Views/MainWindow.axaml.cs`：ShowFlyout 在需要打开任务中心时绑定 MainWindow 的 `OpenTaskCenterForCurrentPage` 实例方法；普通通知的 OnClick 为 null。点击方法从当前 View.DataContext 获取 IPageHost，通过现有工厂创建任务中心。
- 同文件新增私有 `TaskCenterCloseCallback` 类：明确保存页面宿主和 Pane 实例，先创建该对象，再将它的 Close 方法传给工厂，替代嵌套 lambda 捕获。关闭只影响该 Pane 仍为当前内容的宿主，避免旧回调关闭新侧栏；释放该任务中心订阅。
- 创建新任务中心成功后才释放旧任务中心，并按先设置内容、后打开侧栏的顺序更新页面。
- `tests/OneLauncher.RegressionTests/Program.cs`：增加独立的 `--notification-click` Headless 场景，使用隔离数据与真实下载页 ViewModel、任务中心工厂，执行 ShowFlyout 创建的实际通知 OnClick 和任务中心 ClosePaneCommand。
- `tests/OneLauncher.RegressionTests/README.md`：记录独立检查命令与覆盖范围。

不更改三个接口或桌面入口项目。后续新增点击行为可以使用明确的实例方法；需要独立生命周期的关闭行为可参考本次回调对象。

## 验证

回归检查项目及桌面入口编译成功，0 个错误。独立 Headless 场景执行成功，覆盖：

- 普通通知没有打开回调。
- 下载页通知点击创建并打开任务中心，无委托创建异常。
- 重复点击替换任务中心，事件订阅数量保持 1。
- 旧关闭回调不关闭替换后的 Pane。
- 关闭命令关闭侧栏并清除任务事件订阅，重复关闭安全。
- 当前页面无 DataContext 或页面内容为空时安全返回。

本次验证不包含真实 Windows 鼠标事件、原用户进程和 Native AOT 产物。若异常来自此前启动的旧程序集，应关闭该进程并运行此次重新编译的程序；仅热更新不能用于确认已使用本次编译结果。
