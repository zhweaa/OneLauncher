# 侧栏图标主题颜色修复

## 问题与原因

主窗口左侧导航的 8 个图标均为黑色透明 PNG。原先直接用 `Image` 显示，图标像素不会随主题的前景色变化，因此在深色半透明侧栏上难以辨认。

基于 2026-10-22 获取的上游 `master`（`a8fb3ea`），本次生产代码仅修改 `OneLauncher/Views/MainWindow.axaml`。

## 实现

- 保留原有 PNG、32×32 尺寸、导航布局和半透明底材。通过 `Border.OpacityMask` 中的 `ImageBrush` 使用原图透明轮廓，再由 `Border.Background` 绘制颜色。
- 普通状态复用动态主题资源 `PrimaryForegroundBrush`：深色主题为 `#F6F7F9`，浅色主题为 `#202124`，运行时切换主题也会更新。
- 悬停、按下和选中背景沿用现有的 `#777777`、`#666666`、`#555555`，对应图标和文字使用局部 `SidebarActiveForegroundBrush`（白色），避免浅色主题的深色前景落在灰色交互背景上。
- 样式限定于侧栏的 `ListBox.Styles`，未改动后台、导入流程、ViewModel、依赖或发布配置。

## 扩展方式

后续新增单色导航图标时，可复用 `sidebar-icon` 类并为 `OpacityMask` 设置对应的透明 PNG。普通颜色继续跟随全局主题；若调整侧栏交互背景，应同时检查局部交互前景画刷。多彩图标不适合这种单色蒙版方式。

## 验证

- 使用 SDK 10.0.402，按项目原有 `OneLauncher.Desktop/Properties/PublishProfiles/WindowsAot.pubxml` 发布成功：Release、win-x64、自包含、Native AOT、裁剪，保留项目 AOT/裁剪检查。NuGet 还原使用仓库已有的 `NuGet.sandbox.config`。
- 发布得到原生 `OneLauncher.Desktop.exe` 及 4 个配套原生 DLL，没有 CoreCLR 或托管桌面入口残留。编译仍输出上游既有的可空性、MVVM 和 XAML 构造函数等警告，没有编译错误。
- 在任务目录的独立 Avalonia Headless + Skia 预览中，从实际主窗口 XAML 自动生成预览，保留布局、图标和样式，仅替换窗口类、移除业务事件并调整跨程序集资源 URI。检查了 8 张蒙版加载、尺寸、图文前景、展开/折叠、悬停、按下、选中及 Dark→Light→Dark 动态切换；318 项检查通过。
- 已查看运行时渲染截图。Headless 预览用固定明暗底色模拟桌面底材，不验证 Windows Acrylic 与真实桌面的混合效果；没有启动真实账户、初始化游戏数据或执行导入。
- `git diff --check` 通过。

复现构建命令（需具备 Native AOT 的 MSVC 与 Windows SDK 工具链）：

```powershell
dotnet publish OneLauncher.Desktop/OneLauncher.Desktop.csproj -p:PublishProfile=WindowsAot -p:RestoreConfigFile=NuGet.sandbox.config
```
