## 1. 主要结论与改进顺序

当前 UI 已有统一主题、文字层级、卡片样式、页面容器与任务侧栏，适合在现有结构上渐进改善。最有价值的方向是：先稳定布局，再统一状态过渡，最后根据实测消除影响动画的 UI 线程负载。

| 优先级 | 要解决的问题 | 预期结果 |
|---|---|---|
| P0 | 搜索框、下拉框、按钮的尺寸规则不一致；游戏数据卡片长文本被截断或挤到按钮后面 | 工具栏上下边缘对齐，名称以明确的省略号结束，信息与操作互不遮挡 |
| P1 | 页面进入节奏、导航展开、遮罩显隐和按钮反馈不统一 | 页面切换平顺，指针短暂经过导航时不反复展开，侧栏与遮罩具有连续反馈 |
| P2 | 列表嵌套滚动、整组对象重建、图片解码及进度事件频繁派发 | 在较长列表及任务运行时，减少可能挤占动画帧的工作；改进效果以实测为准 |

动画时长变化能够改善感受，但不能直接证明帧率提高。截图只能用于判断静态布局，不能据此认定有掉帧、动画重复或线程阻塞。文中分别标明代码事实、风险推断与后续验证。

## 2. 两张附图的具体问题

### 2.1 附图一：资源检索工具栏

相关位置：

- `OneLauncher/Styles/Controls.axaml:3`：`Button.toolbar-action` 的 `MinHeight=40`，内边距 `12,7`，只设置内容居中，没有规定按钮本体的统一垂直对齐。
- `OneLauncher/Styles/Controls.axaml:107`：`TextBox.search-field` 与 `AutoCompleteBox.search-field` 的 `MinHeight=38`。
- `OneLauncher/Views/Pages/ModsBrowser.axaml:18`：搜索行采用 `*,Auto,Auto,Auto` 网格。
- 同文件第 26–28 行：资源类型下拉框本地设置 `MinHeight=38`、`VerticalAlignment=Center`，没有公共工具栏字段样式。

这些声明能够确认尺寸契约不一致，但不能把截图中的每一像素差异都归因于 38 与 40：TextBox 可能随网格行拉伸，按钮还受到模板、内边距和阴影影响。实施时必须同时检查控件 Bounds 与实际绘制的边框表面。

拟执行操作：

1. 在主题资源中定义工具栏控件高度 40 DIP、条目操作高度 32 DIP，以及已有圆角体系对应的公共尺寸。
2. 在 `Controls.axaml` 中统一工具栏按钮、单行搜索字段和新增的 `ComboBox.toolbar-field`。同一行使用相同目标高度和本体垂直居中，清除造成偏移的本地重复设置。
3. 核对 TextBox 的内容对齐、ComboBox 的显示区域和按钮 ContentPresenter，保证文字及图标的中心线一致。涉及 AutoCompleteBox 时继续检查内部 TextBox，外控件高度相同不能代替模板检查。
4. 保留搜索行的有限宽度网格，明确清除按钮出现时搜索框缩短的行为，保证资源类型和搜索操作仍可点击。
5. 将阴影、边框和焦点提示分开验收。边框对齐以实体表面为准；焦点提示不能被裁切，阴影不计入控件高度。

只修改 `MinHeight` 不能保证最终等高，尤其不能修复父容器把按钮拉伸到 52 DIP 的情况。统一规则只应用于指定角色，不全局强制所有 TextBox、ComboBox 和 Button 都高 40。

### 2.2 附图二：游戏数据页工具栏

`gamedata.axaml:16` 使用固定的 `52,*` 行；工具栏是横向 StackPanel。其按钮默认可以在行高内拉伸，而标签 ComboBox 明确居中且未采用公共高度。这使“新建实例 / 标签过滤 / 重置 / 排序”容易产生不同的边框高度。

窗口的最低宽度为 760，导航展开后内容区进一步减少。横向 StackPanel 没有窄宽度下的换行安排，固定 52 高的标题行也无法容纳换行。

拟执行操作：

- 标签 ComboBox 应用同一工具栏字段样式，按钮本体统一居中。
- 顶部改为受约束的“标题 + 工具区”网格，工具区允许在空间不足时换行；正常窗口继续保持同一行。
- 标题行采用自动高度并保留约 52 DIP 的最小高度，避免窄窗口下第二行被裁掉。
- 保持新建标签特殊项、创建 Flyout、过滤与排序命令的既有行为。

### 2.3 附图二：名称、元信息与按钮互相挤压

相关位置：

- `gamedata.axaml:94–100`：卡片采用 `Auto,*,Auto` 列，名称没有 `TextTrimming`。
- `gamedata.axaml:102`：版本、加载器和标识符放在横向 StackPanel 中。
- `gamedata.axaml:119`：右侧操作区是不可换行的横向 StackPanel，包含默认状态、模组管理、编辑和启动。
- `gamedata.axaml:145`：启动使用 SplitButton；`Button.item-action` 的选择器不会作用于 SplitButton。
- `TransparentListBox.axaml:55`：`data-card` 被统一设为固定高度 96。
- 公共卡片及条目容器多处 `ClipToBounds=False`，用于容纳阴影。

截图中的长名称以不完整单词结束，没有明确的省略提示；标识符靠近或进入灰色按钮区域。代码表明，横向元信息面板缺少对各字段的有限宽度约束，即使每个 `item-meta` 已有省略样式，也不能保证它们在分配的区域内结束。卡片外层又允许越界绘制，这会放大遮挡现象。

拟采用的布局：信息放在上部，操作放在独立的下部行，左侧 64 DIP 图标继续作为视觉锚点。名称和元信息获得完整的信息区宽度，操作不再从名称右侧抢占空间。

```text
┌────────────────────────────────────────────────────────┐
│  图标   Cobblemon Official Modpack [Fabric] …           │
│         版本: 1.21.1   加载器: Fabric   标识符: …       │
│                 [设为默认] [模组管理] [编辑] [启动 ▾] │
└────────────────────────────────────────────────────────┘
```

具体操作：

1. 仅给游戏数据卡片新增专用布局类，避免继续继承 `data-card` 的固定 96 高度。目标最小高度先按约 112 DIP 调整，内容决定实际高度；最终数值以实窗验证为准。
2. 名称使用单行省略、完整名称 Tooltip，并放入受约束的星号列。
3. 元信息改为有限宽度 Grid：版本和加载器优先可读，标识符使用剩余宽度并省略。继续尊重现有“是否显示标识符”设置；空间确实不足时允许信息区增长。
4. 仅在信息内容边界处理裁切。保留卡片外层阴影空间，不能把所有卡片统一 `ClipToBounds=True` 来掩盖问题。
5. 操作区统一间距和垂直中心线；必要时换行，卡片随内容增长。
6. 为 SplitButton 增加独立的条目操作尺寸规则，并核对其主按钮、下拉按钮与内部模板的共同高度。默认徽章按自己的语义保持紧凑，但与操作行居中对齐。

这会略微降低单屏卡片数量，换来更完整的名称和稳定操作位置。相较于引入按窗口宽度切换两套卡片模板，统一的信息/操作分行更容易维护，也不会在调整窗口时突然跳动。

## 3. 整体 UI 设计评估

| 区域 | 已有基础 | 改进方法 |
|---|---|---|
| 窗口与导航 | 半透明窗口底材、稳定图标导航；中央内容不透明 | 保留材质与原有导航视觉，补齐状态过渡和展开稳定性 |
| 标题与工具栏 | 公共 `page-title` 和 `toolbar-action` 已存在 | 对齐实体高度和中心线；窄宽度使用可增长工具区 |
| 管理卡片 | 背景、边框、圆角、阴影及 hover/pressed 已统一 | 为长文本建立有限宽度约束；操作与信息分行；核对同类风险 |
| 资源结果 | 图片、标题、可复制描述和安装入口清晰 | 工具栏固定、结果独立滚动；使用自然行高及明确列间距 |
| 任务侧栏 | PageShell、PaneHeader、模态遮罩已经共用 | 遮罩平滑显隐；核对侧栏开关与内容切换的动画配合 |
| 任务反馈 | 已有状态图标、进度、完成/失败/取消语义 | 补齐按钮过渡；测量并合并高频 UI 刷新；终态立即展示 |
| 主页 | 385 DIP 内容卡片与 300 DIP 启动区形成既有构图 | 保留构图，补齐新闻和导入入口的轻量反馈；检查窄窗口裁切风险 |
| 设置、账户、服务器、版本 | 已复用主题及排版，但页边距和条目操作仍有局部差异 | 先接受公共控件修复；其余局部布局按复现结果逐页调整 |

页面标题的额外偏移量存在 8、9、16 DIP，设置页使用 `40,28`，下载页使用 32 DIP 外边距。统一页边距有价值，但不适合在本轮机械地替换所有页面：下载页有内容宽度限制，主页有明确构图。先对齐本次两个页面与公共控件，其他页面通过截图对照确认后再处理。

账户和服务器也采用“星号信息列 + 右侧操作列”，长名称与横向元信息存在同类风险。它们属于后续验证范围；只有复现后才扩展对应页面修改。

## 4. 动画改进方案

### 4.1 统一时长，但按交互用途分档

建议在 `Theme.axaml` 集中声明动效时长，由现有样式引用。以下是初始调校值：

| 场景 | 建议时长 | 目标 |
|---|---:|---|
| 按下反馈 | 80–100 ms | 点击后立即有反应，释放后顺滑恢复 |
| 按钮、卡片 hover | 120–160 ms | 保留已有轻量反馈，避免突然变亮或阴影跳变 |
| 主页面内容切换 | 约 180 ms | 看清页面变化，同时保持导航响应速度 |
| 遮罩、侧栏内部内容切换 | 160–180 ms | 背景压暗与任务内容出现形成连续过程 |
| 导航展开/收起 | 160–200 ms | 图标位置稳定，标签逐渐出现 |

进入优先使用 EaseOut，退出使用 EaseIn 或较短过渡；避免弹簧、回弹和夸张缩放。时长统一不等于所有场景一样慢。不会新增卡片放大动画，也不会动画化 Margin、Padding 或每张卡片的 Width/Height。

### 4.2 主页面切换

`MainWindow.axaml:160` 当前是 150 ms 的垂直 PageSlide，进入采用 `CubicEaseIn`，退出采用 `CubicEaseOut`。进入从较慢速度开始，可能让新页面的出现显得迟缓；仅缩短时长会进一步压缩可观察的过渡过程。

首轮建议替换为约 180 ms 的 CrossFade，进入 EaseOut、退出 EaseIn，并保留 PageContent 的不透明背景。它可直接使用项目已有 Avalonia 能力，无需新增路由系统或自定义动画类。项目固定使用 Avalonia 11.3.18；本机该版本 XML 文档已确认 CrossFade 具有 `Duration`、`FadeInEasing`、`FadeOutEasing` 和取消令牌契约。

快速连续切换时，要检查最终内容、焦点、透明度恢复以及是否出现旧页面残留。现有页面已创建并复用，不能把“再缓存页面”当作本轮的新优化。若纯淡入淡出经实窗对比仍不合适，再单独评估小位移动效；首轮不直接叠加两种页面动画。

### 4.3 导航展开与标签

代码事实：

- 主导航使用 `CompactInline`，宽度从 62 增加到 152 DIP，展开会改变页面可用宽度。
- `MainWindow.axaml.cs:255–259` 在指针进入、离开时立即设置开关，没有短暂经过的容错。
- 标签直接绑定 `IsVisible`，出现与消失会改变其布局参与状态。
- 导航 hover/pressed/selected 颜色在局部样式中变化，没有项目显式声明的 Transition。

拟执行操作：

1. 使用窗口级、可取消的短延迟处理进入/离开，初值约 150 ms。再次进入取消待收起，离开取消待展开；窗口关闭时释放相关资源。
2. 在导航现有局部样式里增加背景过渡，避免另一套全局导航样式。
3. 调整导航内部标签槽及裁切范围，使图标保持固定锚点，标签用透明度平滑出现。裁切限定在导航自身，不影响页面卡片阴影。
4. 先核对 Fluent 模板现有展开动画，避免在同一属性上叠加第二套过渡。保留 CompactInline 时，明确它仍会触发页面宽度变化，延迟只能减少不必要的触发。

如果实测主要成本来自内容重新排版，可另行尝试 CompactOverlay，让展开部分覆盖页面而不改变其宽度。该方案需要同时解决透明导航表面上的文字可读性、点击范围及关闭行为，不能只改 DisplayMode。它作为有测量依据后的扩展，不属于首轮直接替换项。

### 4.4 任务侧栏与遮罩

`Shells.axaml:19` 已有 160 ms 的 PaneContent CrossFade，它负责侧栏内容变更，并不等同于侧栏开关动画。第 28 行遮罩直接以 `IsVisible` 开关，没有项目显式的淡入淡出。

拟执行操作：

- 遮罩保留在模板视觉树中，以开关状态驱动 Opacity，并使用约 160 ms 的 DoubleTransition。
- 遮罩设置为不参与命中测试；原页面继续由既有 `IsEnabled=!IsPaneOpen` 控制。透明遮罩不能在侧栏关闭后拦截页面输入。
- 保留任务侧栏的显式完成、保存、取消、返回语义；实际检查背景点击不能意外关闭任务。
- 统一 PaneContent 的淡入淡出节奏；分别观察首次打开、内容替换和关闭，避免侧栏移动与内部淡入叠加成重复进场。

PageShell 默认宽度 650 DIP；窗口最小宽度且导航展开时，内容区理论上只有约 608 DIP。是否已有框架裁切需要运行验证。若侧栏标题或返回入口确实不可见，再在 `PageShell.cs` 增加纯视觉的有效宽度约束，保留外部请求宽度契约，不在 ViewModel 硬编码窗口大小。

### 4.5 按钮、卡片、主页与滚动

工具栏和卡片已有 140/160 ms 的 BrushTransition、BoxShadowsTransition，不需要全部重写。缺口主要是 item-action、SplitButton、Pane 主/次/危险按钮，以及主页 NewsCard/Link 的一致状态过渡。

拟在真实绘制属性所在的模板表面增加过渡，并补齐正常态与退出态，使快速 hover/pressed 切换也能恢复。样式要覆盖按钮内容的正确层级，不能假定给 Button 本体加 Transition 就会平滑模板中的颜色变化。

卡片阴影当前从 `0 4 14 1 #32000000` 变为 `0 8 24 2 #42000000`，与工具栏强阴影一起使浅色页面显得较重。建议适度降低 hover 阴影幅度，保留边框和背景变化；是否减少渲染成本需测量。Pane 内只作信息展示的静态表面也不必全部随指针抬高阴影，可逐步限定交互表面。

滚动保持原生滚轮、触控板与滚动条行为，不追加通用“每次滚动都缓动”拦截。资源检索的外层 ScrollViewer 包裹 StackPanel 和 ListBox，可能使列表在无限高度下布局，削弱虚拟化并造成工具栏随列表滚走。建议改成有限高度网格：标题、搜索行、状态区在上方，结果 ListBox 使用自身滚动。

资源卡片内部 `*,*` 行改为 `Auto,Auto`，设置明确的列间距，并核对安装按钮与内容的垂直关系。图片仍使用固定占位尺寸，避免异步图片到达时改变卡片布局。搜索状态预留稳定的单行位置，较长错误说明允许增长。

## 5. 真正影响流畅度的性能候选

以下项有代码依据，但没有本次现场耗时或帧时间数据，不能作为已确认的性能根因。

| 候选 | 代码事实 | 有证据后执行的局部改进 |
|---|---|---|
| 实例列表刷新 | `GameDataPageViewModel.cs:141–145` 在 UI Dispatcher 中重建全部 GameDataItem；构造时同步读取和解码图标 | 按实例 ID 复用展示对象，更新变化字段；图标缓存明确失效条件和释放归属 |
| 搜索结果替换 | 类型切换先 `Items.Clear()`，搜索完成后替换整组 ObservableCollection | 先采用固定工具栏及明确加载状态；需要复用旧结果时避免把旧类型结果当作可安装的新结果 |
| 任务创建 | TaskCenterPaneViewModel 在创建事件中重建完整队列展示对象 | 复用已有任务项，仅插入新增任务，保留各项事件订阅与 Dispose 生命周期 |
| 进度 UI 刷新 | `TaskCenterPaneViewModel.cs:134–139` 每个进度事件都会刷新或向 UI Post | 合并已排队的重复刷新，读取最新快照；必要时限制进度展示频率，完成/失败/取消立即刷新 |
| 首次启动工作集中 | MainWindow.OnOpened 一次创建其余七个页面及 ViewModel | 与现有启动卡顿分析协调，先测量；本轮不直接修改初始化入口 |

进度合并使用现有事件驱动，不新增轮询后端状态的常驻 Timer。若需要显示频率限制，它只处理已到达的 UI 更新；终态不能被延迟进度覆盖。侧栏关闭后，待派发更新也不能恢复已释放的内容。

本项目已有 `启动与整合包安装UI阻塞分析及行动文档-20261023.md`。其中记录用户已经排除初始化等待语句作为此前卡顿原因，本次不会仅因 `GetAwaiter().GetResult()` 的写法重新把它认定为根因。工作区中的整合包安装修复也已有进行中的变更，实施时必须以最新代码重新核对，不覆盖其他任务。

“减少动画”是后续可选体验改进。首轮保持动效参数集中，便于统一关闭或缩短；不为此自行修改 Core 配置模型。若需要新增持久化开关，而后端尚未提供契约，再按前端规范交由项目贡献者补齐，不影响本轮布局与动画修复。

### 7.1 操作顺序

6. 编译、执行布局检查、检查实际桌面窗口和动画中间状态，更新本文为执行结果。

### 7.2 布局验证矩阵

- 窗口逻辑尺寸：760×500、880×560、1200×800；导航收起/展开分别检查。
- 缩放：100%、125%、150%、200%；Light/Dark 两种主题。
- 实例：普通名称、附图中的整合包名称、很长的中英文名称；默认/非默认、原版/模组实例；标识符显示/隐藏。
- 资源：三种资源类型、清除按钮显隐、无结果、加载中、搜索失败、长标题及长描述。
- 覆盖层：标签创建 Flyout、启动 SplitButton 菜单、首次打开侧栏、侧栏内容替换、关闭后的页面交互。

工具栏实体边框的上下偏差目标不超过 1 个物理像素；DIP Bounds 也要一致。名称出现省略号而不是被按钮硬截断；元信息与操作区不交叠，完整名称可通过 Tooltip 查看。卡片阴影、焦点提示、滚动条均保持完整，点击与键盘导航不受透明覆盖层拦截。

### 7.3 动画和性能验证

静态 Headless 截图用于布局和颜色，不能证明真实窗口流畅。需在实际桌面窗口检查快速连续导航、指针跨越导航边界、侧栏反复开关、任务运行时滚动及搜索结果更新，观察中间状态。

在相同窗口、缩放、数据量和渲染环境下对比基线与修改后结果，记录刷新/布局耗时、帧时间及长帧数量。可按 60 Hz 环境的约 16.7 ms 帧预算观察压力，不预先承诺固定帧率。验证重点是减少超过帧预算的工作和长停顿，而不是只看动画总时长。

快速输入后最终页面正确；页面透明度恢复正常；没有旧页面残留、空白闪帧、动画结束后的位移或卡片越界。进度终态立即展示，迟到进度不能覆盖完成、失败或取消；关闭窗口后没有遗留视觉计时器和事件订阅。
