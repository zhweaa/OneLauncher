# 光影包安装后端实现

日期：2026-10-23。

## 用意与入口

在现有 `ResourceInstallerService` 增加 `InstallShaderPack`，供调用方将 Modrinth 光影包安装到指定游戏实例。方法沿用 `InstallMod` 的进度元组和参数顺序，接收光影项目 ID 或 slug、`GameData`、可选 SHA1 校验开关以及取消令牌。

```csharp
await unitedCore.ResourceInstallerService.InstallShaderPack(
    progress,
    shaderPackId,
    instance,
    verifySha1: true,
    cancellationToken: cancellationToken);
```

`progress` 允许为 `null`。服务已通过 `UnitedCore.ResourceInstallerService` 暴露，无需新增注册或修改前端。

## 安装逻辑

1. 校验入口参数和取消状态。
2. 通过共享 HTTP 客户端请求 Modrinth 项目版本列表，以 `instance.VersionId` 作为 `game_versions` 筛选条件。项目 ID 和 JSON 查询参数均做 URL 编码。
3. 不传入实例 Mod 加载器筛选条件，不检查 Iris、OptiFine 或其他依赖是否安装，也不发起依赖项目请求。
4. 取 API 返回的首个兼容版本，优先选择 `primary` 文件；没有标记时取第一个文件。版本列表为空、文件缺失、URL 无效或文件名越界时明确失败。
5. 将远端文件直接下载到 `instance.InstancePath/shaderpacks/<filename>`，保留包文件，不解压或修改光影启用配置。
6. 复用公共文件安装流程，检查已有文件，下载缺失或长度不符的文件。启用 SHA1 时校验全部相关文件，包括已存在的文件。
7. 下载及校验完成后报告 100% 和“处理完成！”。下载器存在取消后直接返回的路径，公共流程在下载后和最终报告前额外检查取消状态，避免误报成功。

元数据请求使用取消令牌并释放响应与流。JSON 读写使用现有源生成上下文；缺失 SHA1 时沿用下载器的跳过校验行为。

## 文件与职责

| 文件 | 改动与职责 |
| --- | --- |
| `OneLauncher.Core/Services/ResourceInstallerService.cs` | 新增光影安装业务入口；Mod 安装改为调用公共文件流程 |
| `OneLauncher.Core/DefaultComponent/Resource/ResourceFileInstaller.cs` | 提取共用的文件检查、并发下载、可选 SHA1 校验与完成通知；使用现有下载器及全局并发设置 |
| `OneLauncher.Core/DefaultComponent/Resource/ResourceGetterService/Modrinth/GetShaderPackModrinth.cs` | 获取兼容光影版本、选择主文件、校验下载 URL 与文件名，生成 `NdDowItem` |
| `OneLauncher.Core/DefaultComponent/Resource/ResourceGetterService/Modrinth/JsonModelGet.cs` | 增加 `primary` 字段及 `string[]` 源生成元数据；保留原类型命名空间 |
| `tests/OneLauncher.ResourceTests/OneLauncher.ResourceTests.csproj`、`Program.cs` | 独立离线测试入口，使用隔离目录与 HTTP 替身 |

公共流程沿用现有下载器的重试与临时下载文件机制。对所有文件均已存在的情形，最终百分比修正为 100%；进度转发不额外引入一次 `Progress<T>` 调度。原 Mod 项目及依赖解析逻辑保持在原组件内。

## 后续扩展

新增其他需要按清单下载的资源时，可由对应元数据组件生成 `List<NdDowItem>`，并复用 `ResourceFileInstaller.InstallAsync`。新增来源、指定光影版本或额外兼容策略，可扩展光影元数据组件，保持业务入口和文件安装流程的职责独立。

本次不增加光影搜索、前端安装按钮、依赖自动安装、自动启用或本地包导入。`InstallShaderPack` 的输入是 Modrinth 光影项目标识。
