# 通知点击任务中心类型转换修复

## 原因

`MainWindow.PageContent.Content` 保存的是页面 View，例如 `OneLauncher.Views.download`，而 `IPageHost` 由页面的 ViewModel 实现。直接将 View 强转为接口会在点击通知时抛出 `InvalidCastException`。

原点击回调还没有判断 `openTaskCenterAfterClick`，并且设置任务中心内容后没有将 `IsPaneShow` 设为 true。

## 修改

修改 `OneLauncher/Views/MainWindow.axaml.cs` 的 `ShowFlyout` 点击回调：

- 仅在 `openTaskCenterAfterClick` 为 true 时打开任务中心。
- 从点击时当前页面 Control 的 `DataContext` 获取 `IPageHost`，使用类型模式匹配。页面或 ViewModel 尚未就绪时直接返回，避免空引用及强制类型转换异常。
- 通过现有工厂创建 TaskCenterPaneViewModel，先设置 `PaneContent`，再设置 `IsPaneShow = true`。
- 替换已有任务中心时释放其 ViewModel；关闭新任务中心时关闭侧栏并释放事件订阅。Dispose 已具有幂等保护，兼容主页原有的释放逻辑。

通知仍通过 UI Dispatcher 显示。点击时读取当前页面，因此通知显示后切换页面，任务中心会在点击时所在的页面打开。关闭回调捕获实际宿主，避免之后切换页面时关闭错误页面的侧栏。

## 扩展

新的页面只需给 View.DataContext 设置实现 IPageHost 的 ViewModel，即可支持此入口。普通通知默认不打开任务中心；需要该行为的消息显式传入 `openTaskCenterAfterClick: true`。

## 验证

`dotnet build OneLauncher.Desktop/OneLauncher.Desktop.csproj --no-restore --nologo -v minimal -clp:ErrorsOnly` 成功，0 错误、87 个警告。未运行实际图形界面点击验证。

建议交互检查：在下载页点击带打开标记的通知、切换页面后点击、点击普通通知，以及任务中心返回关闭与重复打开。
