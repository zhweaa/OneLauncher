# 标签筛选与下拉框修复

日期：2026-10-23。直接修改实际项目 `E:/OneLauncherProject/OneLauncher`。

后续用户要求将重置操作移入下拉框，并在验证后删除临时测试文件。此文记录标签修复过程；临时标签测试代码、入口和依赖已按后续要求撤除，最终交互与清理结果见 [标签下拉框重置操作](标签下拉框重置操作-20261023.md)。

## 问题原因

1. 标签 ComboBox 的 ItemTemplate 同时用于下拉列表和收起后的选中项，因此“移除标签”按钮出现在工具栏字段中。
2. GameDataPageViewModel.OnSelectedTagChanged 只有特殊项判断，没有执行筛选；选中实际标签仍展示全部实例。
3. RefList 重建标签展示对象却没有恢复 SelectedTag，保存实例或标签后筛选选择会失效。
4. 原 Sorting 计算 orderedList 后未使用，反而将 Items 写回完整 Instances。一旦启用过滤，这会丢失当前未显示的实例记录。

## 实现

`OneLauncher/Views/Pages/gamedata.axaml` 为选中项提供纯文字 SelectionBoxItemTemplate，保留下拉列表的删除入口。标签框宽度约束为 168 DIP，长名称以省略号显示，不扩大工具栏；高度继续复用 40 DIP 工具栏样式。

`OneLauncher/ViewModels/Pages/GameDataPageViewModel.cs` 通过统一 RefreshItems 按实例 ID 与 TagMap 的对应关系过滤。未选择标签时显示全部；没有实例关联的标签显示空列表。RefList 捕获标签 ID、重建展示对象并恢复对应选择；重建期间抑制中间的选择回调，只更新一次实例列表，避免临时显示全部结果。删除当前标签后自动回退到全部实例。

Sorting 使用完整实例集合排序并保存，再刷新当前筛选结果；不将过滤后的列表持久化。版本排序通过 Version.TryParse 兼容快照或自定义版本 ID，避免非数字版本抛异常。现有 GameDataManager 已提供标签创建、分配、删除及变更事件，此次未更改后端或数据库格式。

顶部字段负责筛选。操作流程：创建标签 → 在实例卡片“编辑”的标签选项中分配并保存 → 顶部选择标签筛选。新建标签不会自动绑定某个实例，标签删除会清除其关联但保留实例本身。

- 创建特殊项不参与过滤，打开 Flyout；名称去除首尾空白、保存后关闭 Flyout。
- 使用实际编辑 Pane 的 ComboBox 分配标签并保存。
- 标签过滤、保存刷新保持选择、未分配标签空结果、取消关联、重置与删除当前标签。
- Light / Dark、760 / 840 DIP 窗口下，长标签选中项没有删除按钮，字段为 168×40 DIP；下拉列表保留两个真实标签的删除命令。已人工查看浅色工具栏与深色下拉截图。
- 筛选后按版本排序不会丢失其他实例；快照版本可排序，当前筛选保持排序结果。
- 重新加载隔离配置后仍保留全部实例、剩余标签以及正确的标签映射。
