# 魔法按钮主页样式

## 意图

在默认主页（左侧卡片列表 + 右侧快速启动面板）之外，新增“魔法按钮”主页样式：

- 左侧板块（MC新闻、任务中心、联机面板、导入游戏实例）可在设置页单独控制可见性。
- 右侧快速启动面板由右下角的巨大文字按钮代替，按钮只显示默认启动项名称并居中；类型/地址等说明放在 ToolTip 中。
- 悬停时显示阴影，按下时阴影以点击位置为中心快速向四周扩散并逐渐加深。
- 可选背景图片覆盖整个 PageContent；仅魔法按钮样式下可设置和显示。
- 魔法按钮样式下不能在主页选择启动项，只能切换到默认样式或在设置页更改。

## 设置字段（Core，`DBManager.cs`）

- `HomePageStyle`：`Default` / `MagicButton`。
- `IsHomeNewsVisible`、`IsHomeTaskCenterVisible`、`IsHomePowerPlayVisible`、`IsHomeImportVisible`。
- `HomeBackgroundImagePath`。
  - 保存的是启动器复制后的路径，不是用户最初选择的路径。
- `HomeDefaultServerID`：设置时主页默认启动项为该服务器收藏，否则回退到 `DefaultInstanceID`。原 `DefaultServerID` 不受影响。

## 快速启动列表

`HomePageViewModel.cs` 中定义 `IQuicklyLaunchItem`（`Name`、`Description`、`Icon`、`Launch()`），实现有：

- `GameDataQuicklyLaunchItem`：通过 `Game.EasyGameLauncher` 启动游戏数据。
- `ServerQuicklyLaunchItem`：根据 `InstanceId` 查找实例，并携带 `ServerInfo` 启动；实例缺失时通过 `OlanExceptionWorker` 报告。

静态帮助类 `QuicklyLaunchItems` 负责 `Create`、`Signature`（内容变化才重建）、`KeyOf`（`game:id` / `server:guid`）、`Find`、`ResolveDefault`、`SaveAsDefault`。

扩展新的启动项类型：实现 `IQuicklyLaunchItem`，然后在 `Create`、`KeyOf`、`SaveAsDefault`（以及 `ResolveDefault` 如需持久化）中加入对应分支。

## UI 结构

- `Home.axaml`：卡片列表使用 `StackPanel` 作为 ItemsPanel（虚拟化面板会覆盖 ListBoxItem 的 `IsVisible`）；每张卡片外层 Border 接受 card-list 阴影，内层 `home-card-clip` 负责圆角裁剪。
- 有自定义背景时，card-list 加上 `on-image` 类，卡片改用 `Theme.axaml` 中带透明度的 `HomeCardOnImage*Brush`（亮/暗主题各一套）。
- 左侧板块的 ScrollViewer 设置 `VerticalScrollBarVisibility="Hidden"`，仍可用滚轮滚动，但不显示拖拽条。
- 魔法按钮在 `on-image` 下悬停时，底色加深到 `#80000000`，并加 2px 亮色内描边和外阴影，在亮色或杂乱背景下都能看出按钮边界。基础样式统一使用两层 BoxShadow，保证状态切换过渡平滑。
- `Controls/MagicLaunchButton.cs`：在 `PART_BurstLayer` 中放置一个径向黑色 Ellipse，0.42s easeOut 扩散到最远角距离的 2 倍，不透明度 0.18 → 0.72，随后 0.22s 淡出并清理。
- `Styles/Controls.axaml`：MagicLaunchButton 模板与 `magic-launch-title` 样式（居中、58 号粗体）。
- `settings.axaml`：界面板块顶部为“主页样式”和“主页默认启动项”下拉框；板块可见性按钮和背景设置仅在魔法按钮样式下显示。

## 验证

在副本根目录执行（沙盒内需 `UsedAvaloniaProducts=` 跳过遥测任务）：

```powershell
dotnet build tests/OneLauncher.RegressionTests/OneLauncher.RegressionTests.csproj --no-restore --nologo -v minimal -clp:ErrorsOnly "-p:UsedAvaloniaProducts="
dotnet tests/OneLauncher.RegressionTests/bin/Debug/net10.0/OneLauncher.RegressionTests.dll build/magic-home-test --magic-home
```

测试覆盖合并启动列表、卡片阴影、默认样式不显示背景、设置页默认启动项、魔法样式无下拉框、标题唯一且居中、背景下卡片半透明、滚动条隐藏、悬停描边与阴影、爆炸扩散加深与清理、板块隐藏、设置浮层持久化、背景复制到 customdata 及安全删除。测试完成后删除 `build/magic-home-test`。
## 背景图片存储（`Codes/HomeBackgroundStore.cs`）

- 选择图片后先复制到 `%USERPROFILE%\OneLauncher\customdata\home-background\<guid>\<原文件名>`，再把复制后的路径写入 `HomeBackgroundImagePath`；原图之后被移动或删除不会影响主页。
- 每次更换都写入新的 guid 目录，不覆盖主页正在显示（可能仍被占用）的旧文件。
- 保存成功后删除旧副本；保存失败则删除新副本；移除背景时删除当前副本。
- `TryDelete` 只处理 `customdata\home-background` 下的文件，旧配置中指向用户原图的路径永远不会被删除；文件被占用时静默保留。
- 切换到魔法按钮时，若配置中的背景路径为空或文件已不存在（例如配置被不认识这些字段的旧版本启动器重写），会用 `FindLatest()` 找回 `home-background` 中最新的副本并写回配置。
- 因此“移除背景”会清空 `home-background` 下的全部副本，保证已移除的背景不会在切换样式时被找回。
- 测试通过 `HomeBackgroundStore.CustomDataPath` 把目录指向测试数据目录，不会读写用户真实的 customdata。
