日期：2026-10-23。

## 一、目标与当前接入情况

在现有“资源检索”页面提供模组与光影包两种资源的切换、搜索、结果展示和安装。用户选择光影包及目标游戏实例后，调用已经实现的 `ResourceInstallerService.InstallShaderPack`，显示安装进度并将任务接入现有任务中心。

光影安装允许选择原版、Fabric、Forge、NeoForge 或 Quilt 实例，不检查 Iris、OptiFine 是否安装，不提供光影依赖安装选项。目标目录和具体文件下载由后端决定。

已核实的现状：

| 位置 | 当前行为 | 对本次实现的影响 |
| --- | --- | --- |
| `Views/Pages/ModsBrowser.axaml` | 标题已是“资源检索”，输入提示包含光影；结果模板与安装按钮仍绑定 `ModItem` / `ToInstallModCommand` | 可在现有页面扩展两种资源，无需新建导航页面 |
| `ViewModels/Pages/ModsBrowserViewModel.cs` | 只创建 `ModItem`，调用固定模组搜索；构造函数直接启动初始搜索 | 需要区分资源类型、管理查询状态并处理异步异常 |
| `ResourceGetterService/Modrinth/SearchModrinth.cs` | 声明了 `ResourceType.Mod` 和 `ShaderPack`，但 `ToSearch(string Key)` 仍固定 `project_type:mod` 和模组加载器分类 | **光影搜索尚未具备后端接口，是完整前端实施的前置条件** |

## 二、后端前置条件

项目必读文档 `docs/AI_Instruction/AGENT_MUST_READ_FIRST.md` 明确要求：

> 所以如果Agent在设计代码时，发现后端的设计不足以使前端的设计可以解耦，应当中断任务并要求人类修改完后端代码后再继续执行

当前缺口是**光影搜索能力**，不是光影安装能力。后续实际前端实施需等待贡献者补齐搜索接口；不会把 Modrinth URL、HTTP 请求和协议解析搬进 ViewModel 绕过这一要求。本次仅记录建议契约与前置文件，不修改后端。

建议在现有 `SearchModrinth` 增加兼容原调用的参数或重载，例如：

```csharp
Task<ModrinthSearch> ToSearch(
    string key,
    ResourceType resourceType = ResourceType.Mod,
    CancellationToken cancellationToken = default);
```

该能力需满足：

- 模组查询保留原有分类筛选；光影查询使用 `project_type:shader`，不附加模组加载器分类或已安装依赖条件。
- 空关键词返回所选资源类型的热门结果，沿用按下载量排序。
- 查询关键词与筛选条件正确编码；取消令牌贯穿请求和 JSON 读取；响应与流及时释放。
- 复用现有搜索结果模型及 JSON 源生成方式，需要新序列化类型时补充相应上下文。
- 失败传播给调用方，取消保持取消语义，不伪装成空结果或成功。

预期前置改动文件：

| 文件 | 贡献者需要补齐的内容 |
| --- | --- |
| `OneLauncher.Core/DefaultComponent/Resource/ResourceGetterService/Modrinth/SearchModrinth.cs` | 资源类型参数或重载、光影查询条件、取消与资源释放 |
| `OneLauncher.Core/DefaultComponent/Resource/ResourceGetterService/Modrinth/jsonModelSearch.cs` | 若查询参数序列化需要，补充源生成类型；现有结果字段已经足以展示光影 |

## 三、页面与交互方案

### 1. 资源检索

保留现有“资源检索”导航，在页面标题下增加直接可见的“模组 / 光影包”两项切换。默认选择模组，进入光影类型后自动刷新该类型结果。搜索按钮和 Enter 共用一个异步命令，清除按钮正确反映输入是否为空。

页面继续使用 `PageShell` 和 `ListBox.card-list`，结果展示图标、名称、简介及“安装”操作。通过共享展示模型承载共同字段，资源类型决定安装入口：模组打开原 `InstallModPane`，光影打开新增 `InstallShaderPackPane`。

为保留已有模组 Pane 的参数契约，采用以下小范围模型调整：

- 新增 `ResourceItem : BaseViewModel`，保存名称、图标、简介、项目 ID、版本列表和创建时间等公共展示字段。
- 现有 `ModItem` 继承 `ResourceItem`，保留模组加载器信息及现有模组结果转换行为。
- 新增 `ShaderPackItem : ResourceItem`，保存光影搜索结果，保留后端返回的完整版本标识。
- 浏览页面实现 `IListTemplate<ResourceItem>`，`Items` 使用 `ObservableCollection<ResourceItem>`，统一安装命令根据实际项目类型分派。

光影兼容判断不复用 `Tools.McVsFilter` 的正式版过滤结果，避免把搜索结果中有效的快照版本等标识过滤后误判为不支持。支持版本用于展示；最终能否安装以 `InstallShaderPack` 获取实例对应版本的结果为准，不因搜索摘要为空而禁止安装。

查询状态包括加载中、成功但无结果、失败与可重试。切换类型时清理旧类型结果，避免旧卡片暂时作为当前类型呈现。每次查询捕获类型和关键词，并通过取消令牌及请求序号防止较早查询覆盖较新查询；安装按卡片自身类型分派，不能只读取当前页面切换状态。

初始查询也进入同一异常处理流程。取消旧查询不弹错误；业务及未知错误按现有 `OlanExceptionWorker` 处理。新增代码使用 `[ObservableProperty]` 和 `[RelayCommand]`，集合与可视状态在 UI 线程更新。

### 2. 光影安装 Pane

新增独立的光影安装侧栏，复用 `PaneHeader`、`pane-surface`、`pane-status`、`pane-progress` 和现有语义资源。布局包括：

1. 光影名称与返回操作。
2. 游戏实例选择；条目展示实例名称与 Minecraft 版本，原版和各加载器实例均可选择。实例列表为空时显示明确提示。
3. 支持版本信息，以及“安装后可在游戏的光影设置中选择该光影包”的简短说明。
4. 安装阶段、文件数量、进度条与任务状态。
5. 安装、运行中取消、终态返回操作。

不出现模组加载器匹配检查或“同时下载依赖”选项。工厂注入现有 `UnitedCore` 与 `DBManager` 单例并传给 Pane ViewModel；SHA1 开关从 `DBManager.Data.OlanSettings.IsSha1Enabled` 读取，不新增持久化配置。

打开 Pane 时通过共享 `GameDataManager` 获取最新实例列表。开始安装前确认选中实例仍存在且版本标识有效，捕获本次目标实例及光影项目，运行期间禁用目标编辑和重复安装。失败或取消后恢复可操作状态，允许用户重试。

### 3. 任务、进度和关闭行为

- 通过 `UnitedCore.TaskManager.CreateTask` 创建“安装 <名称> 光影包”任务，把该任务的令牌传给 `InstallShaderPack`。
- 后端返回的阶段和数量同步到 Pane 与同一个 `TaskInstance`。元数据阶段总文件数为零时显示准备状态，不进行除法。
- 当前后端可能在下载或校验阶段报告 100%；运行期间显示上限为 99%，仅在安装方法成功返回且未取消后设置最终 100% 和 `SetDone()`。不以百分比或状态文案决定任务已经完成。
- 进度回调检查本次任务身份及 `Running` 状态，避免重试、取消、完成后的迟到回调覆盖终态。
- `OperationCanceledException` 在业务和未知异常之前单独处理，标记取消并显示取消状态，不弹“未知错误”或成功通知。
- 业务错误调用 `SetFailed` 与 `OlanExceptionWorker.ForOlanException`；未知错误调用现有未知异常处理入口。
- 安装开始和成功时发送 `MainWindowShowFlyoutMessage`，可通过现有通知点击入口查看任务中心。
- 运行中返回作为明确的“取消并返回”，调用任务取消后关闭 Pane；任务继续由原异步流程收尾。成功、失败和取消后保留终态信息，用户通过明确返回操作关闭。
- 页面传给新 Pane 的关闭回调检查 `PaneContent` 是否仍是该 Pane，防止通知点击已经打开任务中心后，旧安装回调关闭当前任务中心。

上述防护在新增 Pane 与页面内实现，复用现有任务事件。无需修改 `TaskManager`、任务中心 ViewModel 或主窗口通知机制。

## 五、实施顺序与验证

后端搜索能力补齐后，按下列顺序实施：

1. 接入共享展示模型、资源类型切换与后端查询，完成查询状态和结果分派。
2. 实现光影安装 Pane、ViewModel 与工厂，接入目标实例、已有安装服务及任务中心。
3. 完成编译绑定、DI 注册、取消和终态保护，检查原模组安装入口。
4. 使用离线 HTTP 替身验证搜索类型切换、旧请求覆盖防护、空结果、失败重试和卡片分派；验证原版及各加载器实例均可发起光影安装且不查询依赖。
5. 验证未选择实例、实例已删除、没有兼容版本、SHA1 失败、取消、重复点击、任务中心取消、旧 Pane 关闭回调及安装完成后的迟到进度。
6. 检查浅色/深色与最小窗口宽度下的资源检索页、安装 Pane、空实例状态、运行及终态截图；实际窗口检查焦点、Enter、模态遮罩和取消返回行为。
7. 完成前端、完整解决方案和相应回归项目构建，复跑现有通知点击测试及资源后端测试，撰写实现说明。
