# 任务中心可接入点排查

日期：2026-10-23。仅分析现有代码，未修改业务代码，未执行构建或运行验证。

## 范围与接入方式

检查 OneLauncher 的页面、面板和调用工具，OneLauncher.Core 的业务服务、管理器、下载、认证、资源、联机和服务器组件，并核对控制台启动入口。按用户操作归并，底层网络请求、单文件下载、认证子步骤不重复计算为独立业务任务。

任务入口为 `OneLauncher.Core/Global/TaskManager.cs:76` 的 `CreateTask`。创建后入队并触发 `OnTaskCreate`，任务中心无需新增专用卡片即可显示；进度使用 `SetProgress(current, progress)`，前端按 0–100 显示，结束使用 `SetDone`、`SetFailed`、`Cancel`。应将任务自带的 `Token.Token` 传递到实际执行链，单纯创建任务不能实现实际取消。

## 已有版本安装任务内部可补充的阶段

以下是已有任务中的步骤，不必重复创建顶层任务。当前 TaskManager 没有父子任务关系；若要任务树，需先由后端开放结构。

- `DownloadMinecraftProvider.cs:106` 自动安装 Java：已有取消传递，但未传入 JavaManager 的字符串进度，用户无法直接看到 Java 下载/安装状态。
- 同文件 `:30` 主文件下载：未向当前 progress 单独报告主文件阶段；前端虽有 DownMain 映射，不能据此认定该阶段已有完整报告。
- 同文件 `:55` 库下载后解压 natives：下载进度已有，解压操作未报告独立阶段；Task.Run 的令牌不等于内部解压过程可中断。
- 同文件 `:80` 加载器安装：加载器文件下载和处理器消息已上报，可细化处理器计数；通常继续使用版本任务即可。
- 同文件 `:101` 日志配置下载：没有向 progress 明确报告 DownLog4j2 阶段。
- `DownloadPaneViewModel.cs:154` 之后创建游戏实例、设置默认实例：版本服务完成登记后发送 Done，但这些外层步骤仍未结束，任务可能过早显示完成。
- 游戏启动中的令牌刷新、authlib-injector 下载和语言设置已位于启动链；可补细阶段，不应全部重复成为新的顶层任务。

## 现有接入需先修复的缺口

1. **整合包导入失败后停留 Running**：`HomePageViewModel.Import` 的 task 定义在 try 内部，外部 catch 仅显示异常，没有 `SetFailed`。取消也未单独捕获，可能进入未知异常处理。成功时未显式写入最终 100%。
2. **令牌刷新部分路径不结束任务**：`UserModel.IntelligentLogin` 创建任务后，微软缓存账户为空直接返回；外置账户刷新后未 SetDone；catch 吞掉异常未 SetFailed。也没有传递任务令牌或报告阶段，任务中心的取消可能只改变卡片状态。
3. **Java 进度不代表实际百分比**：安装开始前先上报 100%，随后字符串回调上报累加的 1–28，成功时未补最终 100%；已计算的 progressPercentage 未使用。`Close` 直接取消 `_cts`，而 OperationCanceledException 分支没有同步 task.Cancel，关闭面板可能留下 Running。
4. **版本任务结束边界过早**：DownloadPane 在 DownProgress.Done 回调中 SetDone，但外层仍需保存实例和默认实例；任务可能先显示完成，随后外层操作失败又转为失败。进度回调已有 Running 状态检查，迟到的 Done 回调不会覆盖既有失败。Debug 配置下通用异常 catch 被编译条件排除，异常时也可能缺少正确终态。
5. **终态缺少统一保护**：TaskInstance.SetDone/SetFailed/SetProgress 未限制调用时机；迟到回调能覆盖已取消/失败状态。新增接入需要使用局部任务变量并检查状态，后端也可考虑提供统一的终态转换保护。
6. **取消能力无法按任务区分**：任务中心 CanCancel 仅判断 Running，CreateTask 总创建 CTS，尚无 CanCancel 能力声明。对未接入实际取消链的操作，不能把卡片取消等同于工作停止。
7. **任务历史无限累积**：TaskQueue 无删除/清空与变更事件，面板每次任务创建都会重建整个列表。新闻翻页、Ping 等频繁短操作全部接入会使历史膨胀；应合并批量操作或继续使用页面反馈。

## 建议顺序

先修复现有导入、Java、令牌刷新和版本下载的终态问题，再接入已有进度/令牌接口的模组安装与整合包导出。随后处理实例复制、删除和服务端安装，最后补齐认证、皮肤、联机的后端事件与取消接口。自动短请求按需要接入，避免每个网络请求生成独立任务。
